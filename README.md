# Soul collecter

공개 배포본 「사자의 서」를 기반으로 복원·수정한 Canvas 액션 로그라이트입니다. 기존 영웅 55명의 전투 데이터는 그대로 유지하며, 유일한 8성 타락한 신의 파편를 추가했습니다. 영웅 56명, 무기 95개, 스토리 28개와 4권의 콘텐츠가 들어 있습니다.

원본 TypeScript 소스를 받은 프로젝트가 아닙니다. 공개 JavaScript의 난독화를 해제한 복원본이며, 일부 보조 함수·지역 변수의 이름은 남아 있습니다. [출처](docs/PROVENANCE.md), [구조](docs/ARCHITECTURE.md), [검증 범위](docs/QA.md)를 확인하세요.

## 실행

게임 클라이언트는 외부 패키지를 설치할 필요가 없습니다. Node.js 22 이상에서:

```bash
npm run check
npm test
npm run build
python3 -m http.server 8080 --directory dist
```

`http://localhost:8080`을 엽니다. HTML 파일을 직접 더블클릭하는 방식은 지원하지 않습니다. 이동 A/D, 점프 W 또는 Space, 공격 J, 대시 Shift, 상호작용 F입니다. 키 설정과 모바일 터치 조작도 제공합니다.

기본 모드는 이 브라우저에 저장하는 로컬 계정입니다. 다른 기기와 기록을 공유하려면 본인 Firebase 설정이 필요합니다. 기존 개발본과 같은 저장 키·파일 형식을 유지하므로 이름 변경 후에도 기존 기록을 사용합니다. 사자의 탑 출정 중 저장은 제거하고 나머지 이력은 보존합니다.

## 0.4.0 규칙

| 계약 | 5성 | 6성 | 7성 | 8성 |
| --- | ---: | ---: | ---: | ---: |
| 일반, 8성 잠김 | 3% | 0.3% | 0.03% | 0% |
| 일반, 8성 해금 | 3% | 0.3% | 0.03% | 0.003% |
| 별의 나침반, 해금 전 | — | 95% | 5% | 0% |
| 별의 나침반, 해금 후 | — | 94.9% | 5% | 0.1% |

일반 계약의 나머지는 4성 14%와 3성입니다. 8성은 영웅 계약에서만 등장합니다. 기존 천장(5성 이상 60회, 6성 이상 120회, 7성 이상 360회)과 10회 계약의 4성 보장은 유지합니다. 표는 천장을 제외한 기본 확률입니다. 자연 추첨된 8성을 천장이 7성으로 바꾸지 않습니다. 나침반에는 천장이 없습니다.

- 유물은 일반 45% / 희귀 30% / 에픽 20% / 전설 5%를 먼저 추첨한 뒤 등급 안에서 균등하게 선택합니다. 보유 유물·같은 선택창의 중복도 허용합니다. Lv1에서 시작하여 중복마다 Lv+1, 최대 Lv5입니다. Lv5 유물은 이후 선택지에서 제외됩니다. 기본 수치 효과 +35%가 누적됩니다. 발동 확률은 100%를 넘지 않으며 발동 간격·지속시간·부활 횟수는 늘리지 않습니다. Lv2~5에서 추가 레벨당 모든 피해·최대 체력 +0.5%가 추가됩니다. 문장과 세트는 종류당 한 번만 셉니다.
- 보스러쉬는 선택한 권에서 클리어한 스토리의 보스들을 고정 순서로 반복합니다. 한 순환이 끝나면 첫 보스로 돌아갑니다. 강제 최종 종료는 없습니다. 일시정지 → 포기로 나와도 처치 보상을 정산합니다. 사망해도 처치 보상은 받습니다. 0체 처치에는 보상이 없습니다.
- 완료 순환 수를 c라 할 때 다음 순환의 적 배율 비율은 `1.45 + 0.08c`, 보상 배율 비율은 `1.55 + 0.10c`입니다. 각 비율을 누적 곱합니다. 같은 순서의 보스끼리 비교하면 보상 상승률이 더 높습니다. 매 순환마다 스킬1·스킬2·궁극기 쿨타임에 0.5초를 더합니다. 쿨감 계산 후 더하며 교대·대시는 제외합니다.
- 히든 보스 출현은 첫 일반 보스 처치 시 0.001%, 이후 일반 보스 처치마다 +0.001%p입니다. 한 출정 안에서 누적하며 새 출정 때 초기화합니다. 일반 보스 사이에 추가 전투로 등장하며 기존 순서를 건너뛰지 않습니다. 5페이즈를 모두 넘겨 처치하면 8성 계약이 계정에 영구 해금됩니다.
- 타락한 신의 파편은 근접 타격과 원거리 투사체, 원형 7성 대비 기본 공격력 8배·체력 10배, 스킬 배율 5배와 짧은 쿨타임을 사용합니다. 모든 피해 +100%, 스킬 피해 +200%, 보스 피해 +100%, 흡혈 15%, 받는 피해 −60%의 패시브와 궁극기의 완전 회복·최대 체력 100% 보호막을 가집니다. 모든 문장에 해당하며 명중 시 화상·출혈·감전·독·냉기를 순환 적용합니다. 기존 엔진에 별도의 속성 상성표는 없습니다.
- 공용 영혼 결정의 체력·공격력·스킬 강화는 상한과 진행 바가 없습니다. 비용은 `300 × exp(L×ln(1.12) + 0.00045×L²)`를 10단위로 반올림합니다. 레벨이 높을수록 비용 비율 자체가 커집니다. 나머지 영구 강화의 상한은 유지합니다. 표시 재화명은 영혼 결정으로 통일합니다.
- 인연은 평균 희귀도 R, 평균 돌파 A에 따라 `(1 + (R−3)×0.2) × (1 + A×0.12)` 배율을 받습니다. 두 영웅을 보유하면 편성하지 않아도 해당 인연마다 공격·최대 체력·스킬 피해에 `0.5% × 배율`이 상시 적용됩니다. 편성 인연과 함께 적용됩니다.
- 사자의 탑은 출정·랭킹·칭호 목록에서 제거했습니다. 업적과 칭호를 각각 14개 추가했습니다.
- 주간 마감은 한국 시간 일요일 0시입니다. 스토리 진행도·무한 종합·보스러쉬 종합의 1위에게 부문별 별의 나침반 2개, 공동 1위 모두 지급합니다. 권별 기록 중 높은 무한 층수/보스 처치 수가 종합 기록입니다. 디버그·제외 계정은 지급하지 않습니다. 온라인은 서버가 지급 문서를 생성하고 접속 시 한 번 반영합니다. 8주 이내 미수령 보상을 조회합니다. 로컬은 이 기기의 계정끼리만 집계합니다.

현재 재화와 배율은 JavaScript Number로 계산합니다. 게임 상한을 따로 두지는 않지만 극단적으로 큰 값의 정밀도·표현 범위는 유한합니다. 초장기 무한 플레이를 위한 임의정밀도 재화 엔진은 포함하지 않습니다.

## 무기 픽업과 개발자 도구

무기 계약 화면에서 T키 또는 선택 버튼으로 7성 무기를 지정합니다. 7성이 나온 경우 선택 무기 50%, 다른 모든 7성 합계 50%입니다. 기본 7성 확률 0.03%를 유지하므로 천장 제외 선택 무기 확률은 0.015%입니다. 픽뚫 후 다음 7성 확정을 추가하지는 않았습니다.

개발자 코드는 온라인 계정 UID에 등록하며 전체 계정을 합쳐 한 번만 소진됩니다. 최초 계정은 제한된 보조 개발자 코드를 발급할 수 있습니다. 보조 계정은 코드 발급/다른 유저 초기화를 할 수 없습니다. 두 역할 모두 랭킹과 주간 보상에서 제외됩니다. 설정의 개발자 도구에서 실제 확률, 사용자 세부 장부, 쿠폰, 테스트, 무결성 검사에 접근합니다. [개발자 등록·권한 안내](docs/DEVELOPER.md)에 서버 초기 등록 명령이 있습니다.

## 공개 배포와 운영

[공개 배포 안내](docs/PUBLISH.md)에 GitHub Pages와 Firebase의 실제 절차를 정리했습니다. `.github/workflows/pages.yml`이 검사·테스트·빌드 후 Pages로 배포합니다. `dist/`만 올리면 게임은 실행되지만 온라인 계정·전체 이용자 순위·일요일 서버 집계가 자동 생성되지는 않습니다.

개발자 도구는 **Ctrl+Shift+F10** 또는 설정 메뉴에서 엽니다/닫습니다. 현재 온라인 계정이 코드로 등록된 개발자인지 서버에서 검증합니다. 이전 비밀 문구·관리자 문서·로컬 비밀번호로 켜는 방법은 제거했습니다. 최초 개발자 등록 코드 원문은 최종 전달 메시지에 별도로 제공하며 소스에는 해시만 보관합니다.

| 경로 | 역할 |
| --- | --- |
| `src/game.js`, `src/game-data.js` | 복원한 전투·장면·원본 콘텐츠 |
| `src/engine/` | 고정 틱, 도트 출력, 컬링·상태 갱신 |
| `src/config/economy.js` | 계약 확률·성장 비용·처치 보상 |
| `src/config/expansion.js` | 반복 배율·유물 중첩·인연·8성·히든 보스 |
| `src/config/content.js` | 스토리 문장과 난이도 |
| `src/systems/` | 출정 정산·주간 보상 조회 |
| `src/features/` | 편성·육성·계약·도감·업적·운영자 창 |
| `functions/` | 일요일 온라인 랭킹 집계 함수 |
| `firebase/` | 접근 규칙·인덱스 |

온라인 서버 설정과 실기기 화면·장기 플레이 검수는 별도로 필요합니다. 전투·계약·랭킹 제출은 현재 클라이언트가 계산하며, 변조 방지를 완성한 상용 서버 구조는 아닙니다. [운영 범위](docs/OPERATIONS.md)를 참고하세요.
