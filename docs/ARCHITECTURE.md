# 구조와 최적화 판단

Phaser 공식 문서, 공개 BrowserQuest 렌더러, melonJS의 재사용 패턴을 조사했습니다. 비공개 유명 게임의 내부 구현을 전부 확인한 것은 아닙니다. 현재 프로젝트를 다른 엔진으로 교체하면 전투 판정·스킬 동작의 회귀 위험이 커지므로 기존 Canvas 엔진에 확인한 패턴을 적용했습니다.

## 적용한 변경

1. 원본에도 60Hz 고정 업데이트는 있었습니다. 새 루프는 이를 유지하면서 숨긴 탭의 누적 시간을 초기화하고, RAF 취소와 렌더 예산을 관리합니다. 120·144Hz에서도 시뮬레이션과 애니메이션 경과는 동일한 틱에 따릅니다.
2. 렌더 메서드에 있던 애니메이션 전이와 복귀 위치 갱신을 고정 업데이트로 옮겼습니다. 출력 횟수가 게임 상태를 바꾸지 않게 합니다.
3. 정수 물리 픽셀 배율을 우선하고 DPR과 CSS 크기를 함께 계산합니다. backing canvas는 크기가 달라졌을 때만 재설정합니다. 픽셀 아이콘과 축소 스프라이트의 스무딩을 끕니다.
4. 스프라이트 import와 이미지 디코드 실패를 처리하고 1회 재시도합니다. 준비 전에는 기존 생성형 기본 스프라이트 fallback을 유지합니다.
5. 엘린의 넓은 사망 프레임이 잘리던 96px 출력을 160px 전체 프레임 규격으로 통일했습니다. 모든 별도 아틀라스의 소스 사각형·앵커·애니메이션 프레임 참조를 검사합니다.
6. 화면 밖 적과 픽업의 출력 호출을 생략하되, AI와 충돌 업데이트는 유지합니다. 파티클·잔상의 생존 목록은 새 배열 대신 같은 배열에 압축합니다. 보스가 있는 방에서 반복되던 적 목록 배열 생성은 내용이 변할 때만 수행합니다.
7. 코드 내부의 base64 PNG를 별도 파일로 옮겨 JavaScript 파싱과 캐시 책임을 분리했습니다. 이미지가 사라진 것이 아니라 별도 전송되는 것이므로 전체 전송 비용은 별도로 계산해야 합니다.

현재 구조는 완전한 서버 권위형 게임으로 재작성한 것이 아닙니다. 경제·정산·루프·출력은 별도 모듈로 옮겼고, 복원한 전투·프로시저 그래픽의 많은 기존 내부 함수는 `game.js`에 남아 있습니다. `docs-symbol-map.json`에서 원래 식별자와 주요 복원 이름을 확인할 수 있습니다.

## 측정 해석

`build-metrics.json`은 분석한 활성 번들과 새 src의 실제 파일 크기·gzip 크기를 비교합니다. 스크립트에 있던 이미지가 별도 PNG가 되었으므로 JS 감소율을 곧바로 FPS 향상이나 전체 다운로드 감소율로 해석하면 안 됩니다. 동일 시드의 실제 브라우저 전후 프레임 시간은 아직 측정하지 못했습니다.

정적 배경 캐시와 효과 객체 풀링은 좋은 패턴이지만 이 개발본에서 새로 완성했다고 주장하지 않습니다. 이미 방에 따라 움직임이 많고 기존 캐시도 있으므로, 실제 프로파일링 없이 모든 렌더를 dirty-rect 방식으로 바꾸지 않았습니다.


## Soul collecter 확장 구조

순환 배율·히든 확률·유물 중첩·인연·8성 정의는 `config/expansion.js`에 모았습니다. 배율은 이전 순환의 계산 결과를 캐시하여 반복 계산을 줄입니다. 유물은 고유 ID마다 한 번만 빌드하고 레벨을 수치에 반영하므로 중복이 늘어도 트리거 목록이 복제되지 않습니다.

공용 무제한 강화의 가격은 함수로 계산합니다. 최대 레벨 크기의 배열을 생성하거나 UI가 무한한 강화 칸을 반복하지 않습니다. 보스러쉬와 무한 모드는 체크포인트를 보관하며, 난수 상태와 히든 추가 전투 상태도 복원합니다.

스프라이트는 브라우저의 native import를 사용합니다. 기존 배포용 preload 헬퍼에 남아 있던 미정의 오류 처리 함수가 성공한 import까지 실패로 바꾸던 문제를 제거했습니다. 이미지 디코드 재시도와 기본 스프라이트 fallback은 유지합니다.

주간 지급 함수는 `functions/weekly.js`의 독립 로직을 Firebase의 예약 핸들러가 호출합니다. 클라이언트는 자신의 지급함을 한 번의 인덱스 조회로 읽고, 서버가 만든 지급 기록만 반영합니다. 다른 이용자 전체 저장을 게임 클라이언트로 내려받지 않습니다. 전투 결과와 재화 원장은 여전히 클라이언트 계산이므로 지급 기록을 서버에서 생성한다고 게임 전체가 서버 권위형이 되지는 않습니다.


개발자 권한은 `functions/development.js`가 관리합니다. 클라이언트 저장의 역할 표시는 권한의 근거가 아닙니다. 기존 관리자 직접 쓰기 규칙을 닫고 코드 소진·쿠폰 생성·유저 초기화·확률 수정은 서버 함수를 거칩니다. 배포 해시 기준은 빌드 때 생성하며 신뢰할 수 있는 소유자 터미널에서 서버에 고정합니다. 개발자 계정의 기존 랭킹은 등록 트랜잭션에서 제거합니다.
