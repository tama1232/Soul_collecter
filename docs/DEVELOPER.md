# 개발자 코드와 계정 도구

최초 개발자 등록 코드는 본인 Firebase 서버의 초기 등록 명령에서 무작위로 새로 발급합니다. 원문과 검증용 해시는 게임 파일·공개 Git 저장소·배포 ZIP에 포함하지 않습니다. 이전 전달 메시지의 고정 코드는 이 공개 배포본의 신규 등록에 사용하지 않습니다. 본인의 Firebase 서버 배포와 아래 초기 등록을 완료해야 합니다.

무료 Spark 운영은 [FREE-BACKEND.md](FREE-BACKEND.md)의 설정을 따릅니다. 아래 Functions 배포는 무료 전용 구성에서 실행하지 않습니다.

## 최초 등록

1. [공개 배포 안내](PUBLISH.md)의 Firebase 프로젝트·Email/Password·Firestore·도메인 설정을 완료합니다.
2. Node.js 22에서 서버 의존성과 Firebase CLI를 설치하고 로그인합니다.

```bash
npm ci --prefix functions
npm install -g firebase-tools
firebase login
npm run build
firebase deploy --project YOUR_FIREBASE_PROJECT_ID --only firestore:rules,firestore:indexes,functions
```

3. Google Cloud CLI가 설치된 본인 컴퓨터에서 Application Default Credentials로 로그인합니다. 또는 해당 프로젝트의 권한이 있는 Cloud Shell을 사용합니다. 인증 키 파일을 게임 코드나 공개 저장소에 넣지 않습니다.

```bash
gcloud auth application-default login
node functions/bootstrap-owner.mjs YOUR_FIREBASE_PROJECT_ID
```

이 명령은 최초 실행 시 무작위 코드를 만들고, 그 해시는 서버에만 저장하며 원문은 본인 터미널에 한 번 표시합니다. 원문을 안전하게 보관하고 공개 로그에 남기지 마세요. 확률 기본값과 현재 빌드의 파일 해시 기준도 서버에 등록합니다. 기존 최초 개발자 등록 정보를 다른 코드로 바꾸지 않으며, 이미 등록된 계정의 역할을 다시 만들지 않습니다. 재배포 후 같은 명령을 실행하면 새 파일 해시 기준을 갱신하고 기존 개발자·확률 설정은 보존합니다.

4. 게임의 온라인 계정으로 로그인한 뒤 **설정 → 쿠폰 코드 입력**에 위 명령이 터미널에 표시한 최초 코드를 입력합니다. 이 코드로 먼저 등록한 한 계정만 최초 개발자가 됩니다. 코드의 한 번 사용 제한은 모든 계정을 합쳐 적용됩니다.
5. **설정 → 개발자 도구** 또는 **Ctrl+Shift+F10**을 엽니다. 역할은 서버의 계정 UID에 붙습니다. 다른 계정으로 바꾸면 이전 계정의 권한이 따라가지 않습니다. 게임 진행 데이터를 초기화해도 서버 개발자 이력은 지우지 않습니다.

## 역할

| 기능 | 최초 개발자 | 보조 개발자 |
| --- | --- | --- |
| 실제 계약·나침반·유물 확률 조회/수정 | 가능 | 가능 |
| 유저 목록·영웅/무기/재화/통계/저장 변동 조회 | 가능 | 가능 |
| 일반 쿠폰 생성 | 가능 | 불가 |
| 로그인 시 전체 캐릭터·공개 장 자동 해금 | 가능 | 불가 |
| 원하는 보유 재화 수량 직접 입력 | 가능 | 불가 |
| 테스트 재화·콘텐츠 해금·디버그·회복 | 가능 | 가능 |
| 변경 장부·무결성 검사 | 가능 | 가능 |
| 보조 개발자 코드 발급 | 가능 | 불가 |
| 다른 유저 계정 데이터 초기화 | 가능 | 불가 |
| 랭킹 참여·주간 순위 보상 | 제외 | 제외 |

최초 계정에서 발급하는 코드는 보조 개발자용이며, 한 번 사용하면 소진되고 미사용 상태로 30일이 지나면 만료됩니다. 부개발자는 일반 쿠폰 제작도 할 수 없습니다. 화면에서 항목을 숨기고 Spark 요청·Functions 처리·Firestore 직접 쓰기까지 메인 개발자만 허용합니다. 요청 본문에 owner를 넣거나 UI를 조작해도 서버가 DB 역할을 다시 검사합니다. 새로운 최초 개발자를 발급하는 게임 내 기능은 없습니다.

등록 시 기존 랭킹 문서를 제거하고, Firestore 규칙에서 개발자 이력이 있는 UID의 랭킹 재등록을 막습니다. 주간 집계도 서버 개발자 문서를 직접 확인하여 dbg 표시가 조작되어도 지급하지 않습니다. 클라이언트는 해당 계정을 D/랭킹 제외로 보관합니다. 기존 `admins` 문서, 옛 비밀 문구, 로컬 계정 비밀번호만으로 개발자 권한을 얻는 경로는 사용하지 않습니다.

## 편의 기능

- 메인 개발자 자동 해금: 서버가 확인한 owner 계정은 코드 등록·로그인·권한 동기화 시 현재 56개 캐릭터(8성 포함)를 소유하고 현재 공개된 4장·28개 스토리에 진입할 수 있습니다. 기존 캐릭터 성장과 실제 클리어 기록은 유지합니다. 미공개 장은 열지 않습니다.
- 원하는 재화 설정: **개발자 도구 → 플레이 테스트**에서 영혼석·영혼 결정·별의 나침반·각성 파편·1~4장 정수 중 하나를 선택하고 보유할 수량을 입력합니다. 0 이상의 안전한 정수만 받으며 메인 개발자의 현재 계정에 적용하고 서버 장부에 기록합니다.

- 실제 확률: 퍼센트 입력 폼과 서버 설정 버전, 8성 해금 전/후 확률, 무기 픽업 비율을 표시합니다. 합계가 맞지 않으면 저장되지 않습니다. 다른 개발자가 먼저 수정하면 새로고침 후 다시 저장해야 합니다. 정상 접속자는 최대 약 1분 안에 설정을 동기화합니다.
- 계정 세부 기록: 50개씩 읽고 아이디/UID로 검색합니다. 상세 화면에서 재화·영웅·무기·돌파·최고 기록·기존 저장 장부와 무결성 보고를 확인합니다. 최초 개발자의 초기화는 대상 UID를 다시 입력해야 실행됩니다. 초기화는 진행·재화·유닛을 새 계정 기준으로 만들고, 조작 설정과 중복 지급 방지 수령 이력은 보존합니다.
- 쿠폰(메인 개발자 전용): 코드·설명·만료일·영혼석/영혼 결정/나침반/각성 파편을 입력합니다. 일반 쿠폰은 계정당 한 번만 사용합니다. 개발자 코드와 일반 보상 쿠폰은 별도 영역입니다.
- 테스트: 현재 개발자 계정의 재화 +100만, 전체 영웅/무기/스토리/8성 해금, 현재 방 회복·쿨 초기화, 좌표·실행 상태 확인을 제공합니다. 디버그를 켜면 기존 1~5 테스트 키와 픽업 강제 선택도 같은 권한 안에서 동작합니다.

## 외부 개입 확인 범위

서버가 만든 확률 문서의 해시와 실행 중 확률을 대조하고, 서버에 고정한 배포 파일 해시와 실제로 내려받은 JavaScript를 대조합니다. 불일치는 `integrityReports`에 기록합니다. 개발자가 변경한 확률은 이전값/새값/계정 UID/시각을 `developerAudit`에 남깁니다. 기존 저장 봉인·재화 증가 장부도 상세 화면에 함께 제공합니다.

이것은 설정/배포 파일 불일치와 저장 변동을 확인하는 도구입니다. 공격자가 브라우저와 네트워크 응답을 전부 통제하면 클라이언트 검사도 속일 수 있습니다. 모든 전투 결과·뽑기·재화 소비를 서버가 계산하는 구조까지 완성된 것은 아닙니다. 이러한 제한을 숨기거나 외부 변조가 전부 탐지된다고 표시하지 않습니다.

Firebase 설정이 비어 있는 로컬 플레이에서도 일반 게임은 실행됩니다. 전체 계정의 코드 소진·권한·초기화·전역 쿠폰·주간 지급은 온라인 서버 없이는 동작하지 않습니다. 로컬 저장 플래그로 관리자를 흉내 내는 대체 경로는 두지 않았습니다.

## 비공개로 미리 받은 최초 개발자 코드 등록

미리 전달받은 코드를 쓰려면 저장소에 기록하지 말고 신뢰할 수 있는 터미널에서 입력합니다. 프로젝트와 ADC 설정을 마친 뒤 실행하세요.

```bash
read -rs -p "최초 개발자 코드: " SOUL_OWNER_CODE
export SOUL_OWNER_CODE
node functions/bootstrap-owner.mjs YOUR_FIREBASE_PROJECT_ID
unset SOUL_OWNER_CODE
```

이 명령은 서버에 코드 해시만 저장합니다. 기존 최초 코드나 개발자 계정이 있으면 교체하지 않습니다. 등록 전에는 게임 쿠폰 창에서 사용할 수 없습니다.
