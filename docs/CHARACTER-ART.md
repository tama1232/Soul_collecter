# 캐릭터 이미지 교체와 모션

완성된 `character_crops_52.zip`의 53개 PNG에서 **56명, 총 448개 자세**를 `public/assets/characters/`와 `src/config/character-art.js`에 연결했습니다. PNG 원본은 다시 그리거나 재압축하지 않고 그대로 보존합니다. `scripts/character-art-map.json`이 원본 번호와 게임 ID의 대응표입니다. 소유자가 지정한 대로 **source 1-1은 네메아(anima)**입니다.

`source_07/source7-세레스,드라칸,아스트라,마리오네.png`의 위에서부터 순서는 **세레스 → 드라칸 → 아스테라 → 마리오네**입니다. 이 네 캐릭터는 원본 PNG 하나를 공유하고 각 행의 좌표만 다르게 참조합니다. ZIP의 최상위 폴더 유무와 관계없이 재생성할 수 있습니다.

- 각 프레임의 `x/y/w/h`는 PNG 안의 잘라낼 영역이며 `ax/ay`는 그 영역 안에서 캐릭터의 발 기준점입니다. 무기·망토 때문에 이미지 폭이 달라져도 몸과 발의 위치를 기준으로 정렬합니다.
- 전투 출력은 `(80, 88)`에 발 기준점을 맞춥니다. 기존 시트는 160×96, 새 시트는 발 아래 스킬 이펙트를 보존하는 160×128 캔버스를 사용합니다. 원본 좌표는 그대로 두고 모든 자세에 같은 캐릭터 배율을 적용합니다.
- `poses`는 전투 상태와 이미지 프레임을 연결합니다. 공격 준비·타격·회수 프레임은 기존 액션의 `pose`와 타격 이벤트 시간에 맞춥니다.
- `cycles`의 `frames`와 `tick`으로 대기·달리기·피격·사망의 순서와 속도를 정합니다. `tick` 단위는 60Hz 시뮬레이션 한 틱입니다. 대기·달리기는 반복하고 피격·사망은 마지막 프레임에 머뭅니다. `loop`로 개별 사이클의 반복 여부를 지정할 수 있습니다.
- 대기·달리기는 해당 모션을 시작할 때부터 시간을 셉니다. `idle0/idle1`, `run0`~`run5` 별칭이 바뀌어도 사이클은 이어지며 캐릭터 교대 시 초기화합니다. 피격 정지·슬로 모션에는 전투 업데이트와 함께 멈춥니다.
- 공격 프레임 사이에 직접 그린 중간 프레임(예: `attack0_1`)이 있으면 전환 직후 두 틱 동안 사용합니다. 새 타격 판정이나 공격 지연을 추가하지 않습니다.

새 시트의 8열은 대기·이동 두 자세·점프·대시·공격 준비·공격·특수 동작에 대응합니다. 이동은 두 자세 사이에 대기 자세를 넣어 반복하며 대기는 발이 고정된 미세한 호흡 변형을 사용합니다. 별도 피격·사망 그림이 없으므로 피격은 기존 점멸, 사망은 발을 축으로 서서히 넘어지는 동작을 사용합니다. 이 동작을 새로 그린 피격·사망 프레임이라고 표현하지 않습니다.

일반 투사체에는 외곽선·명암·하이라이트를 넣은 픽셀 그래픽과 잔상을 적용했습니다. 기존에 별도 그림이 있는 고래·카드 등의 특수 투사체는 고유 형태를 보존합니다. 이미 발사된 투사체는 교대 전 캐릭터 ID를 보존하고, 렌더링이 위치·속도·피해·충돌 정의를 변경하지 않는지 검사합니다.

재생성: `python3 scripts/import-character-art.py /path/to/character_crops_52.zip` (개발용 Pillow 필요). `tests/character-art.test.mjs`가 원본 SHA-256, 전체 56명의 고유 대응, 프레임·행 경계, 배율, 네메아와 추가 4인 대응을 검사합니다.

검증: `npm run check`, `npm test`, `npm run build`. 브라우저에서 대기 → 이동 → 점프 → 공격 → 피격 → 사망과 좌우 반전·교대를 확인하고, 새 이미지 적용 후 발 미끄러짐·무기 위치·화면 잘림을 다시 확인합니다.
