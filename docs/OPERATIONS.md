# 운영 안내

## 배포와 저장

GitHub Pages는 `dist/`의 정적 파일을 제공합니다. 게임 서버나 데이터베이스를 대신 생성하지 않습니다. 기본 계정은 브라우저 localStorage에 보관됩니다. 브라우저 데이터 삭제·다른 기기 사용 시 기록이 이어지지 않으므로 설정의 `.sjsave` 내보내기로 백업합니다.

Firebase 설정을 채우고 서버 함수를 배포하면 본인 프로젝트에서 온라인 계정과 기록을 처리합니다. 개발자 권한은 코드 소진 후 서버의 developers/UID에 등록하며, 최초·보조 역할을 매 요청에 다시 확인합니다. 등록과 권한 범위는 [개발자 안내](DEVELOPER.md)를 확인하세요.

새 개발본은 원본과 별도 저장소 키를 쓰므로 원본 서비스의 기록을 자동으로 가져오거나 덮어쓰지 않습니다. 이전 파일 수동 가져오기는 계정 일치·봉인·진행도 검사를 거칩니다. 비용 변경 이전의 소비액을 자동 환급하는 마이그레이션은 추가하지 않았습니다.

## 경쟁 서비스의 한계

현재 전투·계약·보상 계산은 브라우저가 수행합니다. 중복 정산 방지와 봉인은 실수·일반적인 손상 감지에 도움이 되지만, 클라이언트가 보유한 코드와 키를 악의적인 클라이언트로부터 비밀로 만들 수는 없습니다. Firestore 규칙도 JSON 문자열 안의 모든 전투 결과를 검증하는 구조가 아닙니다.

실제 유료 재화나 신뢰가 필요한 경쟁 랭킹을 운영하려면 다음 작업이 별도 필요합니다.

1. 서버가 출정 ID·시드·현재 버전을 발급하고 소유 계정과 연결합니다.
2. 보상 수령 시 서버 트랜잭션으로 같은 출정 ID의 중복 처리를 차단합니다.
3. 서버에서 비용·계약 결과·재화 변동·랭킹 제출을 검증하고 기록합니다.
4. 공격적인 제출 빈도 제한, 감사 로그 보존, 백업 복구, 개인정보 보관 정책을 운영 환경에 맞춥니다.

이 단계가 배포 설정만으로 이미 완료되는 것처럼 안내하지 않습니다. 현재 콘솔의 온라인 사용자 요약은 본인 Firebase 프로젝트 설정과 코드로 등록된 개발자 권한이 있어야 실제 다른 이용자 데이터를 보여줍니다.

## 참고한 공식 문서

- GitHub Pages custom workflow: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
- Firebase 보안 규칙의 인증·역할 조건: https://firebase.google.com/docs/firestore/security/rules-conditions
- Firebase 웹 앱 설정: https://firebase.google.com/docs/web/setup
- Firebase 허가 도메인·이메일 로그인: https://firebase.google.com/docs/auth/web/password-auth

제공한 Firestore 규칙 파일은 현재 코드의 문서 모양과 접근 범위를 위한 초안입니다. 실제 프로젝트의 Firebase Emulator 및 관리자·일반 계정에서 허용/거부 검증을 마친 뒤 운영에 적용하세요. 이 제작 환경에는 본인 Firebase 프로젝트가 연결되지 않아 실제 서버 규칙 배포·검증은 수행하지 않았습니다.


## 일요일 경쟁 보상

온라인 집계·지급 코드와 배포 명령은 [공개 배포 안내](PUBLISH.md)에 있습니다. 새 예약 함수는 실제 프로젝트에 배포해야 실행됩니다. 서버가 만든 지급함 문서는 플레이어가 쓸 수 없고, 함수 재시도는 같은 주차·부문·UID의 지급 문서를 재생성하지 않습니다. 클라이언트 수령 키도 저장하여 정상 접속에서 중복 반영을 막습니다. 저장 파일을 임의로 되돌리거나 변조하는 공격까지 서버가 검증하는 구조는 아니며, 이를 완성하려면 위의 서버 재화 원장 작업이 필요합니다.

새 주차 키는 일요일 날짜로 변경했습니다. 이전 주차 점수를 억지로 합치지 않으며, 0점·미참여 계정과 디버그/랭킹 제외 계정은 지급 대상에서 빠집니다. 접속하지 않은 우승자도 서버 지급함에 보상이 남고 다음 접속 때 받습니다.
